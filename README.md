# Pongo: 3D Table Tennis

**Version 1.0 (first build)** · Cnmbuck Studios · iOS, Swift, SceneKit, portrait, single player against the AI.

Pongo is an arcade table tennis game built physics first. The ball carries a real 3D spin vector. Spin bends the flight through the Magnus effect, kicks off the table and grabs on the paddle. You play with swipe controls: the direction of your swipe shapes the spin, and its speed sets the power.

> **Testing status, stated plainly.** The simulation core (`Packages/SpinCore`) was built and tested on Linux with `swift test` (60 tests pass). The iOS app was written on a Linux machine with no Xcode. Its only compile check is the GitHub Actions macOS job in `.github/workflows/ci.yml`. **The game has not been run on a physical iPhone or in the iOS Simulator.** Look and feel, frame rate, touch feel and difficulty tuning all still need hands-on playtesting.

## Build and run

### Requirements
- macOS with **Xcode 15 or later** to build and run (the project uses the objectVersion 60 format and a local Swift package). Uploading to TestFlight or the App Store needs **Xcode 26 or later**, because Apple requires the iOS 26 SDK.
- iOS 15 or later. The app targets iPhone only, in portrait.

### In the iOS Simulator
1. Open `Pongo.xcodeproj` in Xcode.
2. Select the **Pongo** scheme and an iPhone simulator.
3. Press **Run** (⌘R). Xcode resolves the local `SpinCore` package automatically.

### On a physical iPhone
1. Connect the iPhone and trust the Mac. On iOS 16 and later, turn on **Developer Mode** under Settings › Privacy & Security.
2. In Xcode, select the **Pongo** target, open **Signing & Capabilities**, and choose your **Team**. A free Apple ID works for personal installs.
3. If Xcode reports that the bundle id `com.cnmbuckstudios.pongo` is taken, change it to something unique, such as `com.yourname.pongo`.
4. Select the device as the run destination and press **Run**. On first launch with a free account, trust the developer profile on the phone under Settings › General › VPN & Device Management.

### TestFlight (install on your iPhone without a Mac)
`.github/workflows/testflight.yml` builds a signed release and uploads it to TestFlight on every push to `main`. You can also start it by hand from the **Actions** tab. Until the secrets below exist, the job only prints a warning. One-time setup, with a paid Apple Developer account:

1. **Create the app record.** In [App Store Connect](https://appstoreconnect.apple.com), go to **Apps › + › New App**. Choose platform iOS, name "Pongo: 3D Table Tennis", and bundle ID `com.cnmbuckstudios.pongo`.
   - If the bundle ID isn't in the list, register it first at [developer.apple.com › Identifiers](https://developer.apple.com/account/resources/identifiers/list).
   - If it's taken, use another ID and set a repository variable `BUNDLE_ID` to it.
2. **Create an API key.** In App Store Connect, go to **Users and Access › Integrations › App Store Connect API › Team Keys › +**. Give it the **Admin** role, which cloud signing needs to create the distribution certificate. Download the `.p8` file (it can only be downloaded once), and note the **Key ID** and the **Issuer ID**.
3. **Find your Team ID** under [developer.apple.com › Membership details](https://developer.apple.com/account#MembershipDetailsCard).
4. **Add four repository secrets** in GitHub under **Settings › Secrets and variables › Actions › New repository secret**:
   - `APPLE_TEAM_ID`: the Team ID
   - `APP_STORE_CONNECT_KEY_ID`: the Key ID
   - `APP_STORE_CONNECT_ISSUER_ID`: the Issuer ID
   - `APP_STORE_CONNECT_KEY_P8`: the whole text of the `.p8` file, including the BEGIN and END lines
5. **Run** the TestFlight workflow from the Actions tab, or push to `main`. Builds take about 10 minutes, then Apple processes them for 5 to 30 minutes.
6. **Install.** In App Store Connect, open the app's **TestFlight** tab and add yourself to an **Internal Testing** group. The build then shows up in the TestFlight app on your iPhone.

The build number is the workflow run number, so every upload is unique. The app declares no non-exempt encryption (`ITSAppUsesNonExemptEncryption = NO`), so builds skip the export-compliance question.

### Command line
```sh
# Simulation core tests (any platform with Swift 5.9 or later, including Linux)
cd Packages/SpinCore && swift test

# App build without signing (macOS with Xcode)
xcodebuild -project Pongo.xcodeproj -scheme Pongo \
  -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build
```

### Regenerating the Xcode project
`Pongo.xcodeproj` is generated by a script so that it stays in step with the source tree. After you add or remove app source files, run this from the repo root:
```sh
python3 Scripts/generate_xcodeproj.py .
```

## Project layout

```
Packages/SpinCore/          Platform-independent, deterministic simulation (no UIKit or SceneKit)
  Sources/SpinCore/

                            paddle contact, trajectory prediction, shot solver, spin readout
    Rules/                  Rally referee, scoring and serve rotation, match state machine, stats

  Tests/SpinCoreTests/      Physics, rules and full gameplay tests
App/Pongo/
  App/                      AppDelegate, GameConfig (branding, palette, settings, ball skins)
  Rendering/                SceneKit arena, table, paddles, ball, spin trail, camera, render-loop bridge
```

The app layer only draws and forwards input. All gameplay lives in `SpinCore`, so the same rules and physics can later run on a server or a peer for multiplayer.

## Implemented features

### Physics
- A fixed **1/240 s timestep** with an accumulator, independent of frame rate.
- **Drag and the Magnus effect** on a 40 mm, 2.7 g ball. Spin is a full 3D angular velocity vector and slowly decays in flight.
- **Swept collisions**: sub-steps cap travel at 8 mm, so the ball never tunnels through the paddle, net or table edge.
- A **spin-aware impulse impact model** with normal restitution, Coulomb friction on the contact-point velocity (spin included), and tangential restitution. Topspin kicks forward off the table, backspin checks up, and sidespin kicks sideways. Paddle hits are a real collision, not a mirror reflection.
- Net and post collisions (net cords and dribbles over), table-edge hits, and the floor.
- A paddle **sweet spot**: off-centre contact loses power.

### Controls
- **One-finger swipe** (default). The paddle follows your finger. When the ball arrives, your swipe is the stroke: up for topspin, down for backspin, sideways for sidespin, fast for power, slow for touch.
- **Drag and flick**. Drag slowly to position the paddle, then flick to strike. The paddle holds its position during the flick.
- An adjustable **touch offset** so the paddle sits above your finger, plus **swipe sensitivity**.
- **Assist levels: Beginner, Standard and Expert.** Assist helps paddle positioning, swing timing and blade angle. It never guarantees a return.
- Input is recorded as **timestamped events**, ready for replays and networking.

### AI
- Three difficulties: **Rookie** (Beginner), **Contender** (Intermediate) and **Vector** (Advanced). They differ only through parameters: reaction delay, speed and acceleration limits, prediction error, aim error, mistake rate, spin use, aggression, placement and maximum shot speed.
- The AI moves its paddle under the same speed and acceleration limits as a physical body and never teleports. It aims with the same shot solver and physics the ball uses.

### Rules and match flow
- Games to **11, win by 2**. Serve changes **every 2 points**, and **every point from 10–10**. **Best of 3** games, with the first server alternating each game.
- Legal serve checks: the ball must bounce on the server's half, then the receiver's. A serve that touches the net and lands in is a **let** and is replayed.
- Rally rules: you must let the ball bounce on your half once, a ball off the table or in the net loses the point, and a volley is a fault.
- An explicit **state machine**: Ready → Serving → Rally → PointEnded → GameEnded / MatchEnded, with only allowed transitions.

### Game modes and UI
- **Main menu** with a live AI-vs-AI attract rally under an orbiting camera, and an opponent difficulty picker. It has only three buttons, all working: **Play, Training, Settings**.
- **HUD**: score, serve indicator, game number and games won, pause button, point callouts, serve hint, and an optional **spin indicator** dial.
- **Pause** menu (Resume, Restart, Main Menu). The game auto-pauses when the app goes to the background.
- **Results screen**: Victory or Defeat, game scores, longest rally, average rally, successful returns, fastest shot (km/h) and max spin (rpm).
- **Training mode**: the AI serves to you endlessly with no scoring. Optional overlays show the spin axis arrow, bounce markers and a contact readout (speed, spin, label).
- **Settings**: opponent, assist level, control scheme, touch offset, swipe sensitivity, ball skin, sound, haptics, spin indicator and training overlays. Settings are saved on the device.

### Visuals, audio and haptics
- A futuristic arena: a reflective floor, glowing pillars, a halo ring, stands, floating particles and bloom.
- A **regulation-proportion table** (2.74 × 1.525 m, 76 cm high, 15.25 cm net) with lines, an under-glow and angled legs.
- A **spin trail** ribbon coloured by spin type. The ball's visible rotation is driven by its actual spin.
- Power-shot camera shake and FOV kick, plus a shadow blob for depth perception.
- **Ball skins**: Classic, Energy and Cnmbuck Orb. They are cosmetic only and all have identical physics.
- Synthesized sound effects (paddle, table, net, point, victory, defeat, menu), so no audio files are needed. Haptics fire on paddle hits and points.

### Multiplayer readiness (not multiplayer itself)
- The simulation is deterministic: seeded RNG and a fixed timestep.
- Input arrives as timestamped events.
- Match state is serializable (`MatchSnapshot` and `PhysicsWorld` are `Codable`).

### Tests (`swift test`, 60 tests)
- Spin direction (Magnus curve for topspin, backspin and sidespin), table bounce with spin, net collisions, paddle collisions including off-centre hits, and tunnelling.
- Scoring, deuce, game and match wins, serve rotation including deuce rotation, the let rule, and state machine transitions.
- Full gameplay: AI-vs-AI matches complete legally, and a scripted touch player sustains rallies at every assist level.

## Assumptions made for v1.0
- **Camera**: a high camera behind the player's end of the table, chosen so the whole table fits a portrait screen with room for the swipe area.
- **Paddle depth is automatic.** Your finger controls the paddle's left-right and up-down position, and the game moves it forward or back to meet the ball. A phone screen has no natural third axis.
- **Stroke shape from the swipe.** Forward paddle speed comes from swipe speed. Swipe direction sets vertical and lateral brush, and assist then nudges the blade angle toward a shot that lands.
- **Serving**: tap to toss, then swipe to hit. If the toss drops untouched, the ball is tossed again with no penalty.
- **Branding**: "CNMBUCK STUDIOS" appears as text. The logo, the Cnmbuck Orb texture and the app icon are **procedural placeholders**. No permanent Cnmbuck logo was invented. To use real art, add images named `CnmbuckLogo` and `CnmbuckOrb` to the asset catalog, and the game picks them up (see `GameConfig.swift`). Replace the AppIcon image as well.
- **No economy.** All ball skins are available from the start, with no currency or unlocks.

## Known limitations
- **Not run on a device or in the Simulator.** See the testing status at the top. The CI job confirms only that the app compiles.
- **Tuning is from simulation, not play.** Assist strength, AI difficulty, swipe-to-stroke mapping, touch offset and camera framing were tuned with scripted bots and numeric checks. They will need adjustment once a person plays.
  - In bot testing, chop (backspin) and sideways swipes sustained rallies well.
  - Pure topspin swipes against strong returns were weaker, which may mean too few successful topspin returns for real players.
- **Performance is unmeasured.** The scene uses bloom, a reflective floor and particles. Older iPhones may need a lower quality setting, which v1.0 does not have yet.
- **Audio is synthesized** and functional, not final sound design.
- iPhone only, portrait only. iPad is not configured.
- No accessibility pass yet: Dynamic Type, VoiceOver labels on the HUD, and a reduce-motion option for camera shake.
